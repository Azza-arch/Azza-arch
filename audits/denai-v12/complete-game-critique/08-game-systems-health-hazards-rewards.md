# 08 — Missing/present game systems: health, hazards, rewards, and the rest

This is the brief's own flagged "critical review area." Every item is classified as **ESSENTIAL / RECOMMENDED / OPTIONAL / UNNECESSARY / CONFLICTS WITH CURRENT VISION / NEEDS PLAYTEST EVIDENCE**, grounded in what actually exists in the source (confirmed, not assumed) plus file 02's references.

**Governing fact, confirmed via source, that shapes every answer below:** DENAI currently has exactly **one damage source** in the entire game — Zone G's river (`player.x>7506&&player.x<7830&&body.bottom>1072` triggers `respawn()`). Every other "failure" in the game (missed jump, wrong puzzle answer) has **zero consequence** beyond walking back or re-testing. This single fact governs nearly every verdict below.

1. **Health/hearts — UNNECESSARY, CONFLICTS WITH CURRENT VISION.** There is nothing to spend health points on: one damage source, zero enemies, zero repeated-damage hazards. A heart system would require inventing new hazards to justify its own existence (see #8/#9 below on why that's also not recommended) — adding hearts *first* and hazards *after* is backwards and exactly the kind of feature-for-its-own-sake the brief explicitly warns against ("if DENAI only has recoverable falls and no damage sources, hearts may be meaningless" — confirmed true, not hypothetical).
2. **Lives — UNNECESSARY.** Same reasoning; also directly conflicts with E1 (Super Meat Boy's own design essay arguing *against* lives systems specifically because they gate how much content a struggling player even gets to experience) — DENAI's actual design (free, instant retry, no life cost) already matches the documented best practice McMillen argued for, confirmed via file 02/E1. Removing nothing, adding nothing — the right call already made.
3. **Fall damage — UNNECESSARY, CONFLICTS WITH CURRENT VISION.** The entire game is built around safe, consequence-free exploration of optional routes (C, crate ledge, F-cave) — introducing fall damage would directly punish the exact behavior (explore off the main path) the level design otherwise rewards with secrets and coins. This would be a net loss for a learning-context game specifically (see #28 below).
4. **Death/restart — RECOMMENDED (already correctly implemented, not absent).** Confirmed present and well-designed: `respawn()` returns to the last checkpoint, no penalty, source comments explicitly reference "no lives/penalty" as an intentional design brief. Nothing to add.
5. **Checkpoints — ESSENTIAL (already present and well-implemented).** 14 checkpoints, gate-aware (file 07), robustly re-validated on load even against a hand-edited save (`save.js`'s `sanitize()`). This is not a gap.
6. **Respawn behavior — ESSENTIAL (already present).** See #4.
7. **Moving hazards — NEEDS PLAYTEST EVIDENCE, leaning UNNECESSARY.** No moving hazard exists (the moving *platform* in F is not a hazard — it carries the player, doesn't threaten them). Given the finding in file 07 that the game is correctly understood as puzzle-first, not platforming-first, a moving hazard would need a clear justification tied to the *math* content (e.g., a timed element reinforcing function composition under pressure) rather than being added for genre-convention reasons alone. Do not add without a specific pedagogical reason.
8. **Environmental obstacles (non-enemy) — OPTIONAL, NEEDS PLAYTEST EVIDENCE.** The river is the one example and it works (file 04, R15 — a real visual hazard with a real, fair, well-telegraphed fail state). A second or third instance of the same *idea* (a zone-specific environmental risk tied to that zone's theme — e.g., a water-level or timing element in E's waterworks) could add stakes without requiring a whole new damage/health system, but this is speculative design direction, not a confirmed need — flag for playtest (file 13), don't implement blind.
9. **Enemies — UNNECESSARY, CONFLICTS WITH CURRENT VISION.** Zero narrative or mechanical justification exists anywhere in the game's dialogue, mission text, or world (checked: `dialogue.js`'s full `LINES` object, every zone's `zone:X` line — none mention danger, conflict, or opposition of any kind; the tone throughout is curious/logistical, "bekalan ni kena sampai ke seberang," never threatened). Adding enemies would require inventing a reason that doesn't currently exist in the story (file 10) and would fight the low-pressure, exploration-friendly tone that currently serves the learning goal well.
10. **Enemy patrols — UNNECESSARY.** Dependent on #9; not applicable without enemies.
11. **Combat — UNNECESSARY, CONFLICTS WITH CURRENT VISION.** Same reasoning as #9; combat has no relationship to teaching function composition and would be pure scope/risk addition with no pedagogical payoff.
12. **Timed challenges — OPTIONAL, NEEDS PLAYTEST EVIDENCE.** `this.elapsed` is already tracked and shown on the completion screen (confirmed, `ui-completion-screen.jpg`) — a *soft* timer (informational, no penalty) already exists. A *hard* timer (fail state) is not recommended without specific evidence it would help rather than add exam-like pressure to a learning context (see file 09's concern about puzzles "feeling like exams").
13. **Platform collapse — UNNECESSARY.** No existing content motivates this; would be a hazard added for genre-convention reasons alone, same objection as #7.
14. **Moving platforms — ESSENTIAL function already present, OPTIONAL to add more.** One exists (F), well-implemented (file 07). A second instance elsewhere (if a zone's theme justified it) is OPTIONAL, not a current gap.
15. **Collectibles — ESSENTIAL (already present, well-implemented).** 9 coins, 2 secret-gated puzzle discoveries, confirmed via `COLLECTIBLES`/`SECRETS`; save-robust (`collectedCoinIds`/`discoveredSecretIds` both independently sanitized against `pick()`/known-id lists). Not a gap.
16. **Secret rooms — ESSENTIAL (already present).** C's upper path and F's cave both function as genuine secret/optional content with real rewards. Not a gap.
17. **Bonus challenges — RECOMMENDED, partially present.** C and F-cave already serve this role for exploration; no equivalent *puzzle-difficulty* bonus challenge exists (e.g., an optional harder function). Could extend the pattern already proven to work, but this is additive design, not a defect.
18. **Progress rewards — ESSENTIAL (already present).** Completion screen shows time/coins/secrets (confirmed, `ui-completion-screen.jpg`); each zone's solve unlocks visible world state (a bridge, a lift) which is itself a strong progress reward (see file 12 on feedback quality).
19. **Level grading — UNNECESSARY, NEEDS PLAYTEST EVIDENCE if proposed.** No grading (A/B/C rank, star rating) exists. For a single-level math-learning context, grading risks turning "I explored and learned" into "I got a worse score than my classmate," which is a real downside for a Form 4 classroom tool specifically — do not add without pedagogical sign-off from outside this audit's scope.
20. **Achievements — OPTIONAL.** None exist. Low-risk, low-priority; secrets/collection % already serves a similar light-completionist pull (confirmed via the `#collection` dialog showing secret count).
21. **Inventory — UNNECESSARY, CONFLICTS WITH CURRENT VISION.** Nothing in the game's content (collectibles are permanent-record coins/secrets, not usable items) would be served by an inventory system.
22. **Unlockable cosmetics — OPTIONAL.** No cosmetic system exists; Chill Boy has one fixed appearance. Low priority, would need new art the brief says not to assume is authorized.
23. **Sound effects — RECOMMENDED, largely already present (not independently verified by ear in this audit).** `SFX` calls exist throughout `mechanisms.js`/`game.js` for jump/land/coin/correct/incorrect/bridge/checkpoint/victory — confirmed present in source as call sites; actual audio file presence/quality was not verified (this audit did not play sound). See file 12.
24. **Music — NOT VERIFIED.** `audio.js` is imported and referenced (`audio.unlock()`, volume settings in `#settings`) but music-specific playback was not checked in this audit; flagged as needing direct listening verification, not claimed either way.
25. **Particle effects — ESSENTIAL function already present.** Dust bursts, sparkle bursts, pulse rings all confirmed present in source with reduced-motion fallbacks (`dustBurst`, `sparkleBurst`, `pulseRing` calls throughout `game.js`). Not a gap.
26. **Screen shake — NOT PRESENT, UNNECESSARY.** No screen-shake code found anywhere; given the brief's own caution against "excessive screen shake or distracting feedback," its absence is not a defect — this is a calm, low-pressure game and shake would work against that tone.
27. **Animation anticipation — RECOMMENDED, partially present.** The lift/bridge sequences use delayed tween starts (`delay:reducedMotion?0:220/320`) before the main motion — a real, if small, anticipation beat, confirmed in source. Not extensively analyzed beyond confirming it exists.
28. **Tutorial — ESSENTIAL (already present, in-fiction, not a separate screen).** Contextual toasts ("A/D untuk bergerak," "Space untuk lompat") appear only once-needed, confirmed via `tutorialMoved`/`tutorialJumped` state flags — this matches B1's "teach without a separate tutorial screen" principle directly, already implemented, a genuine strength.
29. **Difficulty options — NEEDS PLAYTEST EVIDENCE, loosely RECOMMENDED per the Accessibility reference (file 02).** None exist currently beyond the universal `prefers-reduced-motion` handling (confirmed thorough — nearly every animation in the codebase checks `reducedMotion`). Per the Accessibility source (file 02's "Accessibility reference" section): individually-toggleable options, not a single difficulty switch, is the documented best practice — but given DENAI's puzzles have no fail penalty already, the most relevant accessibility gap is not difficulty tuning, it's input/sensory (see file 11).
30. **Replayability — NEEDS PLAYTEST EVIDENCE.** "Main Semula" (replay) exists; secrets/collectibles give a light completionist reason to replay; there is no procedural variation, so replay value is driven entirely by whether the *learning content itself* is worth re-engaging with — a question for the math-education side (file 09), not a systems question.

## Final recommendation for DENAI's core systems

**Do not add health, lives, enemies, combat, or fall damage.** None are supported by the game's actual content, narrative, or current design, and all would require inventing new justification from scratch rather than filling an existing gap — exactly the trap the brief warns against. The one real finding worth pursuing (flagged NEEDS PLAYTEST EVIDENCE, not implemented here) is whether a *second*, modest, theme-appropriate stakes-raising moment (in the spirit of the river, not a new system category) would help the flat challenge curve found in file 07 — and that should be tested with real players before being built, not assumed.
