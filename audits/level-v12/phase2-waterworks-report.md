# DENAI V12 Phase 2 — Applied Math Waterworks Prototype

## Scope and provenance

Implemented an isolated V12 build at `app/addmath/rooftop/v12.html`. Zone E's quiz-to-unlock interaction is replaced with an in-world experiment. V11 remains the comparison baseline; no V11, V10, or V9 source was edited. B, D, F, and G gameplay, the Zone E platforms, pipes, gates, and collision geometry were not redesigned or relocated. The V12 level data changes only the E interaction terminals.

The approved Phase 1 blueprint was not present in the workspace during this implementation. Phase 2 was constrained to the explicit requirements in the user's request; no new objective, math question, or broader world redesign was inferred.

## Implemented experiment

At the two existing E stage locations, interacting with F or G selects which function runs first. The existing output lever starts the experiment. The machine applies the selected functions to input 3, animates water through the existing pipe route, and updates each stage readout from the computed intermediate and output values.

| Chosen order | First stage | Second stage | Result | Water and route |
|---|---|---|---:|---|
| F → G | F(3) = 7 | G(7) = 19 | 19 | Reservoir fills; bridge lowers, then collision is enabled |
| G → F | G(3) = 7 | F(7) = 15 | 15 | Two of three reservoir sections fill; bridge stays closed and the experiment can be retried |

No answer popup is required during the normal interaction. Existing Kenney scenery, pipe, output lever and world platforms are retained; stage names and live values use Phaser text. The input and stage values are generated by `evaluateWaterOrder`, not selected from a display-only result table.

## State and recovery

The explicit states are `LOCKED`, `CONFIGURED`, `RUNNING`, `NON_TARGET_RESULT`, `TARGET_REACHED`, `CROSSING_ACTIVATING`, and `CROSSING_SAFE`.

- Order selection moves `LOCKED` or `NON_TARGET_RESULT` to `CONFIGURED`.
- Activation is accepted from `CONFIGURED` or `NON_TARGET_RESULT`; repeated activation while `RUNNING` is ignored.
- The calculated output moves the run to `NON_TARGET_RESULT` or `TARGET_REACHED`.
- Only target output starts `CROSSING_ACTIVATING`; the collision platform is added after the bridge tween completes, then state becomes `CROSSING_SAFE`.
- Pause/resume retains the running mechanism state. Save recovery maps an interrupted run to `CONFIGURED`, retains `NON_TARGET_RESULT` for another attempt, and resolves a target/bridge animation save to a stable safe crossing only when the stored order is F → G. Invalid or inconsistent target state cannot open the crossing.
- V12 uses its own save key, level ID and layout version. It does not import or mutate V11 save data.

## Confirmed implementation vs. human judgment

**Verified:** the ordered functions produce 19 and 15 from input 3; stage readouts use actual computed values; 15 creates a retryable partial water result; only 19 activates the crossing; the crossing collision is added after the bridge reaches its safe position; reload and pause recovery remain stable; desktop traversal and a mobile touch interaction work in browser automation.

**Unproven until human playtesting:** whether players notice and understand that the two stage interactables choose order; whether the physical route between both controls and the lever feels natural rather than like backtracking; whether the two-of-three water fill clearly communicates “retry”; whether the animation is satisfying and appropriately paced; whether mobile controls feel comfortable on actual devices. Automation does not establish learning, discoverability, enjoyment, or perceived difficulty.

## Design audit note

The Impeccable detector ran in degraded regex-fallback mode because its HTML/CSS parser modules were unavailable; it reported inherited palette/font/radius values outside the repository's current `DESIGN.md` tokens. Since this prototype reuses the existing V11 visual language and no approved V12 design system was found, this phase did not rewrite shared styling or alter V11 documentation to silence those findings. Re-run the detector with parser dependencies available when V12's design tokens are established.
